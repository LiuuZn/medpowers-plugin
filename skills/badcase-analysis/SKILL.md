# badcase-analysis — 错误案例分析与标注质量工程

本技能分两半：**上半是项目无关的定位范式**（从 bad case 入手定位问题层级，先读）；
**下半是打包交付流程**（当定位结论需要给用户交付证据时使用）。**最终交付物是一个
tar.gz 压缩包**，解压后包内三要素缺一不可：① 错误分析文档 `badcase_analysis_report.md`；
② 案例原始影像（cases/ 目录，扁平存放 nrrd）；③ 标注信息（层面/有无等简单标注直接
写在文档表格里；复杂标注另存文件并在文档中引用）。

## 定位范式（项目无关）：bad case 驱动的问题定位

一切从坏案例出发：**先别改模型，先回答「问题出在哪一层」**。五层候选，按证据落点归层：

| 层 | 典型形态 | 判定手段 |
|---|---|---|
| 标注内容 | 标注者点错/漏标/语义口径不一 | 绝对位置核查、oracle 锚点消融、用户审片 |
| 标注管线 | 映射/匹配错位、索引变换、跨序列串号 | 元数据溯源、内容匹配复核、富集分析 |
| 预处理 | 方向/重采样/窗宽窗位/裁剪错误 | 与原始导出逐层比对 |
| 模型 | 能力边界（覆盖不足、解码缺陷） | 锚点消融、误差分布、交叉统计 |
| 评测 | 分母口径、数组长度、单位不一致 | 口径复核（修复前后数字分开陈述） |

每层判定手段不同，**具体问题具体分析**；禁止跳过定位直接调参。

### 八步闭环

1. **单例取证，假设判别**：对用户报告的可疑 case 穷举候选机制（索引逆序/固定偏移/
   跨序列串号/匹配失败/坐标系变换…），为每个假设设计**可否证**的判别实验，逐一
   证实或排除，不轻信第一个说得通的假设（实例：用户猜「逆序索引」，实测镜像落点
   不在声称椎体，假设被否证）；
2. **审计维度升级**：既有检查（簇内顺序/间距）抓不到「整簇位移」，要用**独立于标注
   生成链路的解剖/物理参照**做绝对位置审计（如分割掩码建椎体标尺）。审计工具与
   被审对象必须相互独立；
3. **全量扫描 + 富集分析**：单例定性后立即全量定量，按候选机制维度分组统计错误率。
   **强富集 + 模式集中（错误幅度尖峰、落点贴体积边界）= 系统性管线缺陷；散在本底
   = 人工随机误差**。二者治理路径完全不同：修管线 vs 交用户仲裁；
4. **上游溯源取铁证**：找到标注/数据的原始导出。**元数据是不可篡改的意图证据**
   （如 DICOM 的 SeriesDescription 证明标注在哪个序列上完成，InstanceNumber/
   SliceLocation 给出几何真值）；内容匹配只做佐证。两者矛盾时以元数据几何为准
   （仅当载体只覆盖原序列部分范围时以内容为准，并记录理由）；
5. **重建而非打补丁**：重写生成管线（按序列对齐、全片/全卷指标、显式处理坐标系
   变换），产出**版本化**映射（schema 不变、下游无感）+ 逐目标 diff + 报告，
   不覆盖原件；
6. **独立验证闭环**：用与修复方法**不同通道**的参照验证（如内容匹配修复 ↔ 解剖
   审计复跑；元数据几何 ↔ 内容峰位互证），双通道互证结论才成立；
7. **保守分层治理**：低置信 → 剔除进复核清单（下游按缺失处理）；带不确定性的修复 →
   保守值采纳 + 打标；内容性错误（证据表明标注者真点错）→ 仲裁清单交用户。
   **修管线 ≠ 修标注内容**，边界必须写进报告；
8. **批准点隔离**：数据修复与重训分离，重训前经用户批准；修复时保持 case 划分与
   评测协议不变，保证修复前后指标严格可对照（对照实验只动一个变量）。

### 通用经验（医疗影像踩坑，跨项目适用）

- **坐标系变换是隐形杀手**：轴转置（方阵形状不变、最难察觉）、轴序/片序翻转、
  部分覆盖裁剪、重采样。跨源数据（DICOM ↔ NRRD/NIfTI、不同导出工具）比对前，
  必须先用一例做「已知真值」对齐校准——找到能把同内容对到相关系数 ≈1 的变换，
  再谈批量匹配；
- **弱指标的危险在于部分可用**：只采样 0.4% 像素的中心行/列指标在域内 97% 正确，
  恰好掩盖了域外（跨重建核/跨设备）失效。匹配/配准/分割指标必须在其设计域外
  压力测试后再信赖；
- **警惕巧合式鲁棒性**：中心行指标对轴转置不敏感，是「中心行=转置后中心列」的
  巧合——缺陷因此潜伏整个项目周期。凡指标对某类变换不敏感，追问是设计还是巧合；
- **检查维度要覆盖该错误的全部形态**：内部一致性检查（多目标比大小）抓不到绝对
  位置错误；脏清单会有盲区（本项目 327 例脏清单漏掉 15 例粗大错位），定性新错误
  类型后要回头复核旧清单的覆盖缺口；
- **脏标注的真实危害在评测可解释性**：小容量模型会把脏标注当噪声忽略（剔除重训
  几乎无收益），但 val/test 污染直接扭曲模型选型与归因——修数据的收益主要在
  评测可信度，预期管理按此口径；
- **批量处理前先扫规模分布**：gzip 医学体数据全量解压的内存峰值（如 811 片
  float64 ≈ 17GB）决定并行策略，超限者串行；
- **全程程序化证据链**：脚本 + JSON 产物 + 报告可复现；影像判读结论只来自用户
  审片（可视化红线，见 AGENTS.md）。

与 `methods/label-ceiling-diagnosis.md` 的边界：那边回答「标注噪声把指标天花板压到
多少」（静态量化），本范式回答「坏案例的根因在哪层、管线错的部分如何重建」（动态
溯源与修复）。

## 定位与参考实现

本技能定义**流程与质量纪律**（任务无关）；逐例推理与渲染的工具在**任务仓库**内。
参考实现：`spine_locator` 任务仓库（3D 关键平面定位，plane3d）——

- 逐例导出：`keyplane/export_errcase.py`（逐例预测 + 锚点校验 + 多次判断的分解）；
- 分桶统计：`scripts/analyze_badcases.py`；
- 解剖位置核查：`scripts/audit_annotation_anatomy.py`（用全胸椎分割掩码建立椎体标尺）；
- 全量解剖审计：`scripts/scan_annotation_displacement.py`（椎体标尺判定全部标注
  平面的绝对位置，含逐假设的镜像一致性检验；范式第 2-3 步的参考实现）；
- 标注映射重建：`scripts/rebuild_slice_mapping.py`（同序列优先的全片 ZNCC 匹配 +
  几何迁移交叉验证 + 阈值剔除；范式第 4-6 步的参考实现；重建报告范例
  `runs/mapping_rebuild/rebuild_report.md`）；
- 渲染：`scripts/render_badcases.py`（矢状面全景 + 轴状位标注/预测逐片对比）。

其它任务仓库复用时，按"前置条件"提供等价工具；本技能自带的两支脚本
（遴选、组装）直接可用，路径走 argparse。

## 前置条件（四条，缺则先在任务仓库补）

1. **逐例预测文件** `preds_<split>.json`：每个 (case, target) 至少含
   `true（标注切片）/ pred（最终预测）/ in_win（真值是否被分析窗覆盖）/
   anchor（第一阶段粗定位）/ intrinsic（锚点直接放在标注切片上时各模型的判断）/
   votes（全部窗口判断的汇总）/ vote_std（判断的分散程度）/ native_z_mm（切片厚度）。
   三条口径纪律：
   - **分母 = 全部标注平面**，真值未被任何窗覆盖的样本记为错误，禁止静默剔除；
   - 概率累加数组按例分配长度（固定长度会让厚切片体数据预测恒空——spine_locator
     曾因固定 120 长度漏掉 1mm 薄层病例）；
   - 多偏移投票的每个偏移必须真实生效（曾出现循环变量未加偏移、7 个偏移全部退化
     为 0 的缺陷——用几何口径「任一偏移使 round(anchor+off-true) 落在窗半宽内」复核）。
2. **分桶统计** `badcase_summary.json`：按第 1 步的类别归桶，并附标注结构检查结果
   （顺序颠倒/多目标同片/间距越界）。
3. **渲染工具**：矢状面全景（能看多目标相对位置与扫描范围截断）+ 逐失败目标的
   轴状位标注/预测两行对比；窗宽窗位高反差（CT 骨窗 W800/L200 起步）；线色约定统一
   （绿虚线=标注、红实线=预测、橙线=粗定位锚点）；图上参考点（十字）用分割掩码或
   影像内容定位，**不要用标注元数据里的质心**（可能偏差极大——spine_locator 的
   planes.json 质心偏离椎体达 50-86mm）。
4. **标注源**：标注 JSON（case → 各目标层面索引），用于结构检查与解剖位置核查。
   若做溯源与重建，还需要**标注原始导出**（如 DICOM 原片，含元数据）。

## 第 0 步（必做）：确认 z 轴方向并核查标注的解剖位置

**先确认方向再谈对错。** 本数据集的结论（2026-10-08 确认）：NRRD 头文件
`space directions` 第三行在 LPS 坐标下全部为正（+z 指向头侧），即**切片序号 0 = 足端，
序号向头侧递增**，全数据集一致。复核命令：抽样读 header 看 `space directions[2][2]` 符号。
（范式的「坐标系校准」在本任务的具体化：跨源匹配前先确认方向 + 轴序。）

在此方向约定下做两类标注检查（内部顺序检查不够用，见陷阱清单）：

- **内部顺序检查**：多目标标注之间的相对顺序/间距是否符合解剖（T12、T13、L1
  依次相邻，间隔约 10-15mm）；
- **绝对位置核查**：标注序号是否真的落在声称的解剖结构上。参考实现
  `scripts/audit_annotation_anatomy.py`：用全胸椎分割掩码（TotalSegmentator）建立
  每例的椎体标尺——双肾（类别 2/3）解剖上跨 L1-L3，肾门约平 L2，以双肾质心最近的
  椎体记作 L2，向头侧依次命名 L1、T12……然后判定每个标注片实际落在哪个椎体、
  与声称目标差几节。注意：双肾不在扫描范围内时（33/550 例）无法标定；双肾质心
  最近的椎体已是足端最后一个椎体时（275/550 例），按 L2±1 记，节差判定带 ±1 节
  不确定度（粗大错误 ≥3 节的判定不受影响）。

## 第 1 步：遴选典型案例

```bash
python3 skills/badcase-analysis/scripts/select_typical_cases.py \
  --error-dir runs/error_analysis --mapping <任务仓库>/nrrd_slice_mapping.json \
  --out runs/error_analysis/typical_cases.json
```

五类错误、每类 3-5 例（不足如实写，不凑数），按严重度降序 + split/形态多样性：

| 类别 | 定义 | 归属 |
|---|---|---|
| 标注数值错误 | 标注本身写错：多目标标在同一片（解剖学不可能）、目标顺序颠倒、间距异常（如 ∉[4,30]mm）、或绝对位置落在错误椎体 | 数据 |
| 疑似标注错误（待人工复核） | 标注结构与间距正常，但把定位锚点直接放在标注切片上时，各模型一致地选择其他切片（≥2 个单位） | 数据（嫌疑） |
| 模型错误：锚点偏差超出精化范围 | 标注正常，第一阶段锚点偏差超出第二阶段训练修正范围，整簇锁定到相邻结构 | 算法 |
| 模型错误：粗定位严重偏离 | 标注正常但第一阶段锚点严重偏离，真值未被任何分析窗覆盖 | 算法 |
| 评测工具缺陷 | 独立于模型的口径问题（数组长度不足、分母被静默剔除、单位不一致等） | 评测 |

判定依据两件套：**标注结构检查**（顺序/间距先验，mm 口径）+ **绝对位置核查**
（第 0 步）+ **锚点校验**（把锚点换成标注切片：各模型一致不选标注 ⇒ 外观不支持
该标注，数据侧嫌疑；各模型命中标注但集成失败 ⇒ 算法侧）。案例须同时是"错误"
（任一目标未覆盖或误差 ≥2 个切片单位），阈值放 argparse。

**红线：判定只依据程序化测量与用户审片反馈。** 智能体自行查看渲染图所得的
影像判断（解剖结构、标注位置、对错）一律不作为证据（见 AGENTS.md「医疗影像
可视化红线」）。

## 第 2 步：渲染对比图（生成后交用户查看反馈）

用任务仓库渲染工具逐例出图（入选案例全量）。硬要求：矢状面全景（能看多目标相对
位置与扫描范围截断）+ 逐失败目标的轴状位标注/预测两行对比；图内文字用 ASCII
（避免字体缺字）；多目标的线与文字错开防重叠。产物命名 `<split>__<case>.png`
集中存放，第 3 步收编进包。

渲染完成后**必须请用户查看并反馈判断结论**；智能体不得自行解读影像内容并据以
归因或决策（红线，见 AGENTS.md「医疗影像可视化红线」）。

## 第 3 步：组装并打包（交付物 = tar.gz）

```bash
python3 skills/badcase-analysis/scripts/assemble_pack.py \
  --typical runs/error_analysis/typical_cases.json \
  --img-dir <processed 影像目录> --out runs/badcase_pack
# 错误分析文档写完后打包（交付物就是这个压缩包，不得遗漏）
tar czf runs/badcase_pack.tar.gz -C runs badcase_pack
```

包结构（用户验收硬结构；cases/ 只放 nrrd 且扁平，靠文件名区分，提高逐例查看效率）：

```
runs/badcase_pack/
├── badcase_analysis_report.md   # 错误分析文档（第 4 步撰写，图内嵌引用 figures/）
├── annotations.csv              # 全部典型案例的机器可读标注总表
├── cases/                       # 只放原始影像 nrrd，扁平
│   ├── <case>_val_ori.nrrd      # 原图（本任务为层面标注，无 label/pred 掩码）
│   └── <case>_test_ori.nrrd     # 文件名带 split 区分
└── figures/                     # 对比图（badcase_analysis_report.md 内嵌引用）
    └── <case>_<split>.png
```

命名约定：原图加 `_ori` 后缀；**分割任务**的标注加 `_label`、预测加 `_pred` 后缀
（本任务标注是层面序号，按约定直接写在文档表格里，不生成掩码文件）。

## 第 4 步：撰写错误分析文档（badcase_analysis_report.md）

结构模板：

```markdown
# 错误案例分析报告（<任务/基线名，日期>）
## 0. 口径与总量（分母定义、错误构成表）
## 0.5 数据方向与标注解剖位置核查结论（z 轴方向、绝对位置核查的错标率）
## 0.8 校准参照（一个全部判断正确的病例，先看"对"长什么样）
## 1. 分类总览（五类定义 + 案例数表）
## 2.X 每类一章
### 成因讨论（3-5 句）
### 案例 Xn <case> [split]
| 目标 | 标注切片 | 预测切片 | 误差（片与 mm 双口径） | 粗定位锚点 | 锚点设在标注片时各模型的判断 | 判断分散度 |
诊断解读 3-6 句（引用具体信号；结论句式固定三选一：标注数值错误/疑似标注错误待复核/
模型问题/评测工具问题）
图：figures/<case>_<split>.png；原始影像：cases/<case>_<split>_ori.nrrd
## 3. 交叉统计（标注错误在各类中的富集比、mm 误差量级、跨类共性）
## 4. 结论与建议（按类给行动项）
```

溯源/重建类任务的报告（`rebuild_report.md` 型）另含：缺陷复盘（多层成因叠加）、
新方法要点、匹配质量分布（相关系数分位数、几何一致率）、v1→v2 审计对比表、
三类复核清单（剔除/带标记采纳/内容性错误仲裁）、与训练的交接说明。

撰写纪律（**用户验收红线**）：

- **用朴素、清晰、准确的中文。禁止英文缩写与行话**：不写 oracle / covered /
  intrinsic / vote_std 之类，改用「锚点设在标注位置时各模型的判断」「真值被分析窗
  覆盖」「判断的分散程度」等直述；
- **影像证据只认两类来源**：程序化测量（分割掩码统计、几何计算、指标数值）与
  用户的审片结论。不得出现智能体自行看图的视觉描述（如"图中可见锁骨/双肾"）；
- **禁止自造词**：不发明「坍缩」「粗大标注」这类压缩表述；标注本身写错就写
  「标注数值错误」，并紧跟一句朴素说明（如「T12 与 T13 标在了同一片」）；
- 每个案例的讨论必须引用该例的具体信号（数值、判断），不许只写"模型错了"；
- 切片数与毫米双口径并列（±1 片在不同层厚下物理量差数倍）；
- 「疑似标注错误」必须注明待人工复核，不得当作已证实；
- 评测工具缺陷修复前后的数字不得混用，注明口径。

## 已知陷阱（历史踩坑，动手前过一遍）

- **智能体对医疗影像渲染图的视觉解读不可作为证据**（用户红线）：渲染图交给用户看、
  结论由用户反馈；智能体归因只能引用程序化测量。曾出现智能体"目检确认"后被
  要求作废的情况；
- 内部顺序检查（多目标之间比大小）**不能**发现绝对位置错误：存在标注内部顺序正常、
  但整体标到另一端椎体的病例（spine_locator 已实证一例，绝对位置偏 11 节）。两类
  检查都要做；
- **按患者号前缀 glob 取数据文件会在多序列患者上随机串号**：必须按序列描述/UID
  对齐（本项目 362 例标注在 stnd 序列、体积却取了 lung 序列，跨重建核弱匹配失败
  造成 46 例整簇错位）；
- **本数据集 NRRD 的 x/y 轴相对 DICOM 栅格是转置的**（实测同核原片转置后相关系数
  1.0000 验证）。跨源匹配前必须先做单例对齐校准；
- **内容匹配的几何一致性校验要用对坐标系**：修复后的索引在目标体积坐标系，而
  「N − InstanceNumber」是源序列坐标系的期望值，跨体积迁移的平面不能直接比
  （本项目曾因此误报 46.5% 一致率的假警报，按「源=目标体积」子集重算实为 97.7%）；
- 清单文件必须传**平铺列表**：嵌套 dict 传给 `set(json.load(...))` 会静默变成过滤
  dict 的键名，等于没过滤；
- 排序键里的哨兵值（如未覆盖=999）会被 `max` 当成真实最大值选中，随后又被过滤——
  先分离「未覆盖/有覆盖」再取最差；
- 遴选要保证 split 与「未覆盖/有覆盖错误」两种形态都有代表，否则文档结论有偏；
- 图内凡带索引的访问先裁剪到数据范围（锚点可能解码越界：spine_locator 有 0.3% 病例
  的第一阶段把补零区域的质量计入期望，锚点跑出体数据长度）；
- 渲染参考点用分割掩码或影像内容，不用标注元数据质心；
- ±1 片 ≠ 固定毫米；引用基线数字注明分母口径（全部标注平面 vs 被窗覆盖的子集）。
