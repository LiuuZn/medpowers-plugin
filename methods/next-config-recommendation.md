# 方法论 ③：下一轮训练配置推荐

输入是方法论②的诊断结果，输出是**具体的、可执行的**下一轮训练逻辑/配置变更。

## 原则

1. **一次只改一族变量**（超参族 / 损失族 / 预处理族 / 模型族 / 精度族），否则归因失效。
2. **先便宜后昂贵**：lr 与损失权重/组合 → 训练时长与数据增强 → 预处理 → 换模型（换模型是最后手段，先动备选）。
3. **每项变更必须带预期信号**：明确"若下一轮看到 X，说明该变更有效/无效"，供方法论②检验——这使整个回路可自主迭代。
4. **精度族不用于修复欠/过拟合**：AMP dtype（bf16/fp16）、TF32、FP8 只改变速度/显存与数值误差，不改变模型容量或正则；换精度必须独立对照并做精度验收，规则见 [precision-policy.md](precision-policy.md)。

## 状态 → 变更映射（基线框架，待实验记录充实）

| 诊断状态 | 候选变更（按优先级） |
| --- | --- |
| 欠拟合 | 加大模型容量 / 延长训练 / 降低正则 |
| 过拟合 | 数据增强 / 早停 / 缩容量 / 预处理增广 |
| lr 过高 | 降 lr、加 warmup、平滑调度 |
| lr 过低 | 升 lr、换调度（cosine/poly） |
| 损失分量失衡 | 重加权 / 换损失组合（查 `assets/objectives/`） |
| 指标-目标背离 | 更贴近评价指标的 loss（如直接 Dice 系）或组合 |
| 收敛平台 | 换调度 / 换预处理 / 提容量 |

## 输出契约

输出：变更清单（改哪族、从什么改成什么、为什么能针对性改善诊断出的状态）+ 每项的预期信号 + 下一轮实验记录的编号建议。变更理由须能回溯到诊断证据。
