# assets/objectives — 损失 / 目标函数 / 不可导评价指标

任务无关的三类条目，一个 md 文件一条，命名用通用名（如 `dice-loss.md`、`hd95.md`）。文件内用标签标明类别：`[loss]` 可导损失、`[objective]` 目标函数、`[metric]` 不可导评价指标。

> 条目含代码（`<slug>.py`）时，代码须遵循统一代码规范 [../CODE_STYLE.md](../CODE_STYLE.md)（依赖、自包含、文件头、类型标注、数值稳定、自测块、与资产卡同名配对）。

## 论文支撑（必填，置于条目开头）

用简体中文回答四个问题，每项一两句话，写简单。**条目若含代码，同样把这四问写进代码头部注释**：

- **哪篇论文用了它**：团队/作者 + 简称 + 年份（附链接）
- **目的**：论文用它来解决什么问题
- **效果**：取得了什么提升（有数字写数字）
- **结论**：论文下的结论 / 适用边界

无论文支撑的条目不收录；实在找不到原始论文的，注明出处综述或经典教材，并说明"无直接论文"。

## 其余字段

- **类别标签**：loss / objective / metric（可导性是关键区分）
- **形式**：公式或伪代码
- **适用**：分割/分类/回归、类别极不平衡场景等
- **行为特征**：收敛快慢、对小目标敏感度、与哪些指标配合观察（如 Dice loss ↔ Dice 指标）
- **调参经验**：权重、组合方式（如 CE+Dice 配比）
- **坑**：梯度稀疏、early loss 崩塌、与真实评价指标背离
- **实验反链**：相关 `EXP-*` 记录

## 收录边界

机制与通用经验；某任务实际选用的组合及原因 → 实验记录。
