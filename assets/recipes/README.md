# assets/recipes — 训练配方资产

任务无关的**完整训练配方**（recipe）：优化器与 LR 日程、损失组装（含深监督加权）、
采样策略、混合精度与梯度裁剪、训练时长与迭代结构——把
[../models/](../models/README.md)、[../objectives/](../objectives/README.md)、
[../augmentation/](../augmentation/README.md)、[../preprocessing/](../preprocessing/README.md)
的单项资产**组装**成"逐项抄表即可开工"的整体配方。单项资产讲机制与选型；配方讲
**精确默认值与组装顺序**，两者互补，不重复收录。

## 收录范围与边界

- 一条 = 一个配方卡（一个 md 文件），命名 `<family>-<variant>.md`（如 `nnunet-default-recipe.md`）。
- 配方须有**一手源码考证**：每个默认值注明框架/版本与源码位置（文件:行号），不接受
  "网上教程说"级别的出处。
- 只收任务无关的部分：默认值、组装关系、与单项资产的引用；某任务的实际选用与实测
  （epoch 用时、显存、收敛数字）写进该任务的实验记录（`EXP-*`），配方卡只在"量级"节
  以实例引用并反链。
- 与单项资产的分工：损失函数的数学与行为 → objectives 卡；优化器超参、LR 日程、深监督
  加权与反传序列等"训练循环级"的组装 → 本目录。

## 配方卡字段

- **论文支撑（必填）**：按各目录统一的四问格式，简体中文，注明配方出处论文与所读版本
  （配方通常随框架论文发表，如 nnU-Net 的 Training Scheme）。
- **配方构成**：逐项表——元素 / 精确值 / 源码出处（文件:行号）；组装顺序（伪代码级）。
- **量级**：实例化实测（参数量 / 显存 / 每 epoch 用时 / 总时长），注明任务、数据规模、
  GPU 与来源实验编号。
- **组装关系**：引用哪些 `assets/*` 单项条目（互链）。
- **坑**：口径陷阱（如监控量与指标不可比、日志负值正常）、容易被漏掉的非常规默认
  （如隐藏的梯度裁剪）。
- **实验反链**：使用该配方的 `EXP-*` 记录。

## 代码

条目含代码（`<slug>.py`）时，遵循统一代码规范 [../CODE_STYLE.md](../CODE_STYLE.md)
（自包含、CPU 自测、文件头四问、数值稳定注释）；代码只复刻配方中**框架耦合最深、
最容易抄错**的组件（如 LR 调度、深监督加权、AMP 反传序列），不复制整个训练循环。
